Multi-Tenant Authentication & Dynamic Fleet Branding

Learn how the First Taxis platform eliminates hardcoded configuration files, enabling a single mobile application build to dynamically rebrand its logos, colors, and titles for any partner taxi company.

01 Executive Overview

Historically, taxi driver applications required individual application builds or static configuration constants (e.g. defaultTenantId = 'org_ace_taxis' in constants.dart) to identify the fleet organization. This created operational bottlenecks and prevented white-label deployment.

lightbulb The Core Architectural Philosophy

One Binary to Rule Them All: The app store distributes a single mobile build. When the driver opens the app, they connect once with their Tenant ID and Tenant Key. The server returns full branding metadata (logos, gradients, color tokens), which transforms the app instantly and permanently on the user's device.

02 The 3-Step Driver Lifecycle

The user experience is split into three deliberate states: one-time setup, everyday 2-field login, and in-app settings management.

Step 1 • Initial Onboarding Done Only Once

First-Time Setup (One-Time Prompt)

When a driver opens the freshly installed app, the device checks local secure storage for an existing tenant_id. If none is found, the onboarding modal appears:

  • check_circle Company ID: The fleet slug (e.g., org_first_taxis).
  • check_circle Fleet Access Key: The fleet authentication secret key (tk_live_...).
  • qr_code_scanner Instant QR Scanning: Drivers can scan an onboarding QR code from dispatch to auto-fill both credentials.
verified Validated against POST /api/Tenant/Resolve
Step 2 • Daily Operations Subsequent Logins & Post-Logout

Everyday Work (Clean & Simple)

Once saved locally, subsequent app launches and sign-out states never ask for the Tenant ID or Key again:

  • check_circle Only 2 Inputs: The form renders with strictly Driver Username and Password.
  • check_circle Zero Flicker Branding: Logo, curved crimson header, and app title are loaded from cached secure storage on the very first frame.
  • check_circle Auto-Injection: When the driver submits, tenantId and tenantKey are attached automatically in the background.
domain Includes quick [Change Fleet] shortcut chip
Step 3 • In-App Management Available Anytime in Settings

Changing Companies (From Settings)

If a driver moves to a different taxi company or dispatch rotates their access key, they never need to delete the app:

  • check_circle Navigate to Settings ➔ Fleet & Company inside the app drawer.
  • check_circle Displays current fleet: First Taxis with a green Verified & Active badge.
  • check_circle Tapping "Change Taxi Company" lets them enter or scan new credentials, instantly re-dressing the app!

Database Architecture (SQL Server)

CREATE TABLE Tenants (
    TenantId VARCHAR(64) PRIMARY KEY,           -- 'org_first_taxis'
    TenantKeyHash VARCHAR(256) NOT NULL,        -- SHA-256 hash
    DisplayName VARCHAR(128) NOT NULL,          -- 'First Taxis'
    IsActive BIT NOT NULL DEFAULT 1
);

CREATE TABLE TenantBranding (
    BrandingId INT IDENTITY(1,1) PRIMARY KEY,
    TenantId VARCHAR(64) FOREIGN KEY REFERENCES Tenants(TenantId),
    LogoLightUrl VARCHAR(512) NOT NULL,
    LogoDarkUrl VARCHAR(512) NOT NULL,
    PrimaryColor VARCHAR(9) DEFAULT '#CD1A21',
    PrimaryDarkColor VARCHAR(9) DEFAULT '#9E0E14'
);

04 Client Reskinning Engine

1. Flutter Mobile Shell (`FlutterSecureStorage`)

Upon resolution, the Flutter shell persists the tenant credentials and raw branding JSON locally:

KEY tenant_id
KEY tenant_key
KEY tenant_branding

The TenantThemeProvider Riverpod notifier reads this data on app start, instantaneously building the dynamic ThemeData.

2. Angular Webview CSS Custom Properties

When embedding WebViews, Flutter appends the theme palette to URL query parameters. Angular overrides its CSS variables in :root dynamically:

function applyTenantBranding(branding: TenantBranding) {
  const root = document.documentElement;
  root.style.setProperty('--primary-color', branding.colors.primary);
  root.style.setProperty('--primary-dark', branding.colors.primaryDark);
  document.title = `${branding.name} Driver Portal`;
}

05 Frequently Asked Questions

Does the driver need to enter the Company ID & Key on every shift?

No. They enter it exactly once on first launch. It is cached in hardware-backed encrypted storage. Everyday shifts only require Username and Password.

What happens if a driver logs out?

The app stays locked into their fleet's branding (logo and colors remain active). The login screen resets to show only the 2 fields: Username and Password.

How does a driver switch companies if they change fleets?

They can open Settings ➔ Fleet & Company ➔ Change Taxi Company, or tap the small [Change] button on the login screen. They enter the new fleet credentials, and the app adapts immediately.
